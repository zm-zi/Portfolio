这次大改做了什么

01

航空版画视觉重塑

放弃同质化的深色霓虹特效，改为高对比暖纸底 + 深青墨线 + 朱红点缀的「航迹飞行局」视觉。峡湾和山谷两张地形板通过镜像翻转实现无缝滚动，机体投影与受击闪白提前烘焙到离屏 Canvas，手机端也能稳帧。

02

24 种词条与前置联动

在原有基础词条上扩出冰霜弹（急冻 / 深度冻结 / 碎冰）、闪电连锁（雷霆增幅 / 雷霆充能）、火力核心（需速射+双发前置）以及僚机、追踪导弹树状升级，不同战机有独立的词条过滤条件，避免抽到废卡。

03

三种模式与分岔航线

除 7 关战役航线和无尽冒险外，新增关闭火力的「自由探索」模式。无尽模式到达特定分数会弹出航线分岔：选精英航线硬扛 20 秒换一次额外词条，或者直接走补给航线回血、充能航线补 50 点超频能量。

04

手感判定与自动化冒烟

把玩家碰撞箱从矩形改成贴合机头的三角形，擦弹反馈更利落；同时写了 Python 冒烟测试脚本，自动校验开局、选机、进入战斗和暂停流程，改完代码能马上回归。

实测与复盘

7 人试玩后补了充能视觉反馈

找了 7 位平时玩肉鸽的朋友试玩，统计发现速射（5/7）、僚机（4/7）、穿透（4/7）拿得最多，超频词条只有 2 人选。聊下来原因很直接：击杀充能条太不起眼，打着打着根本不知道快满了。补上击杀能量粒子聚拢和仪表高亮后，超频词条的选取率立刻上来了。

重构时顺手把资源体积压掉了一半多

老版本塞了 36 MB 零散的 PNG 贴图，风格也不统一。重做航空版画后全换成 WebP + 自托管字体子集，整个游戏包从 50 MB 降到 18 MB，加载速度快了不少。

待改进项

36 个脚本目前靠传统 script 标签按顺序加载，下一步值得迁成 ES Module；4 架战机现在开局全解锁，后续可以补一层局外解锁目标，增加多周目动力。

设计取舍记录

01

为什么给「雨燕」锁 320px 射程，给「日冕」单独写穿透规则

雨燕走的是霰弹枪思路：三发 0.8 倍伤害全吃很赚，但如果不限制射程，在屏幕最底端照样能扫全场，近战定位就废了。项目底层没做距离伤害衰减，干脆把子弹射程定死在 320px，逼着玩家往前靠。

日冕的持续激光直接绕过了普通子弹池，按每秒伤害结算。为了不让「穿透弹」对它失效，我给激光单独做了映射：每层穿透给光束加宽 6px，既符合直觉又保留了词条收益。

02

超频为什么绑定「击杀充能」和「无敌 + 双倍射速」

✕
按时间自动充能

玩家容易拖时间等大招，越打越拖沓

✕
受伤充能

生命上限本身紧张，靠卖血换资源体验别扭

✓
击杀充能

持续清怪才能攒满，鼓励主动往前抢输出

实测下来，单给无敌容易只用来保命，单给射速翻倍在密集弹幕里又不敢站桩。两项绑在一起给 3 秒，玩家攒满后才会放心贴脸打一波爆发。

泊车小镇

Three.js + WebGL 2 · 程序化粘土海湾街区 · 4 款原创 GLB 车辆 · 街机泊车模拟

项目介绍

基于 Three.js 做的 3D 低模卡通风泊车游戏。玩家驾驶原创双门教练车穿过海湾医院街区，根据右下角实时 GPS 小地图和地面黄色标线，把车顺向或倒向稳稳停进指定车位，每次精准入位得 100 分并轮换下一处车位。

整个街区没有去买现成大场景包，而是写了一套倒角积木实例化工具 ClayKit 拼出医院、花店、面包房、咖啡馆、海滨码头和灯塔，还用 Node 脚本程序化生成了 4 款带轮轴和车灯节点的原创 GLB 车辆，顺带配了 Puppeteer 自动驾驶脚本做渲染与交互验收。

核心设计与技术实现

01

ClayKit 积木实例化合批

用 14 种共享倒角基础模具（圆角方块、坡顶、伞面、柱体、圆环等）拼装整座海湾街区，去重冗余 UV 顶点后按模具类型打成 InstancedMesh 批量提交，单材质通过每实例着色呈现哑光粘土质感。

02

程序化生成 4 款原创车队

写了构建脚本生成海湾双门教练车、冲浪露营车、面包售卖车、花店小皮卡四款 GLB 资产，统一世界米制尺度与轮子旋转轴；再通过 onBeforeCompile 给共享图集里的车窗色块局部注入斜纹反光 Shader。

03

跟手的街机泊车物理

采用自行车运动学转向模型，最大转向角随车速从 0.62 rad 平滑收窄到 0.20 rad，高速不飘、低速揉库灵活；刹车和倒车切挡阻尼独立调节，配合刹车灯自发光、尾气和手刹扬尘粒子强化反馈。

04

宽容但明确的入位判定

支持车头朝里或倒车入库：当中心偏移落在 |dx| < 0.61m、|dz| < 0.94m，朝向余弦 |cos(heading)| > 0.975（约 ±12.8°）且车速低于 0.13 并稳停 0.65 秒即判定完成，触发彩纸特效与 +100 分。

核心技术方案

01

三种钓法完整状态机

覆盖路亚（抛竿→沉底→方案收线→线长 ≤15m 双确认快收→拉鱼入护）、浮子（追踪底部放大框的黑漂/顶漂自动提竿）和水底三竿轮巡（1/2/3 号竿首抛、收风线、放竿等口，支持 F7 手动抛好后无缝接管）。

02

WASAPI 进程音频 + 2.78 kHz 频谱检测

水底模式通过 proc-tap 按进程 PID 单独采集游戏音频流，做 100ms 汉宁窗 FFT，比较 2.78 kHz 报警音与两侧邻带能量比（峰值 ≥ 5 倍邻带才触发），既能听声提前巡检，又不会被风声水声误触。

03

基于统计分布的拟人化节奏（Humanizer）

抛弃容易被特征拟合的均匀随机 ±10%，改用四层叠加模型：右偏对数正态分布 + Ornstein-Uhlenbeck 均值回复漂移（模拟相邻动作自相关的手快/手慢段落）+ 在线时长疲劳项 + 低概率走神长尾。

04

自适应鱼口节奏与安全兜底

水底轮巡默认按鱼口疏密动态调整等待间隔（有口缩 25%、空轮延 25%，限幅 0.5×~2×）；前台只要人工点了鼠标左键立即抢占暂停并释放所有按键；路亚挂底或异常会发邮件/Webhook 提醒。

猎魂传奇

Unity 2D · C# · ScriptableObject 数据驱动 · 程序化节点地图搜打撤

项目介绍

一款用 Unity 2D + C# 做的节点探索搜打撤原型。玩家带装备进图，逐层选择战斗、宝箱、随机事件或休息节点，最后必须抵达撤离点才能把包里的战利品带回仓库，中途阵亡则本局未撤出的物品全掉。

做这个项目主要是练数据驱动架构：把所有物品、敌人、掉落表和区域规则拆成 ScriptableObject，策划直接在 Inspector 配表，运行时靠事件总线驱动 UI 刷新。

核心系统与分层架构

程序化节点地图

每局按 MapGenConfig 权重随机生成 10—18 层节点（每层 2—3 个），覆盖 6 个区域和 4 档难度，包含战斗、容器、事件、休息、撤离五种节点。

回合制战斗解析

BattleResolver 按攻防、暴击、减伤和吸血公式逐回合结算；胜利走 LootTable 加权掉落，失败触发强制撤离或判定阵亡。

数据驱动装备生成

ScriptableObject 定义模板，ItemGenerator 按品质权重（白/黄/紫/黑/红）和 6 类部位动态生成带随机词条的 ItemInstance。

事件解耦与随机遭遇

DataManager、PlayerManager、InventoryManager 与 RaidManager 职责分离，靠 OnStatsUpdated 等事件刷新 UI，EventResolver 提供 5 类探索事件。

AnimeChatWeb

Next.js · DeepSeek / MiniMax · LanceDB 向量记忆 · Galgame 风格 AI 互动

项目介绍

用 Next.js + React 做的一款 Galgame 界面风格的 AI 角色聊天应用，最初在 Unity 里写过一版，后来觉得以文字、UI 和流式接口为主的项目用 Web 技术栈迭代更快，就把整套模块逐一迁到了前端。

重点搭了亲密度、四维情绪、手动触发的向量记忆检索和动态开场场景四块系统，并做了陌生人、成长、陪伴者三个入口，适配想慢慢培养关系和只想直接聊天的不同习惯。

系统与技术架构

流式对话与标签解析

DeepSeek SSE 流式输出，带行级缓冲拦截结构化情绪与亲密度标签，避免 TCP 分片把 JSON 截断，前端按标点节奏逐字打出。

亲密度与情绪联动

亲密度范围 -100 到 +100 分 10 个阶段，单次变动落在 [-2, +1]，再乘以当前情绪系数（0.5~1.4）；连续发相似话术会触发 0.3 倍衰减防刷好感。

手动入库的向量记忆

用「保存记忆」按钮代替每轮自动抽取，避免把无意义寒暄塞进库里污染上下文；对话时由 DeepSeek Function Calling 按需从 LanceDB 检索 3—5 条相关记忆。

三模型按任务分工

DeepSeek 负责主对话，MiniMax 生成开场场景卡片降低等待延迟，DashScope 1024 维接口做中文向量嵌入；另配 /admin 角色编辑器和 Debug 调试面板。

复盘与文档

按交互形态选技术栈省了大量时间

从 Unity 切到 Next.js 后，毛玻璃面板、三层景深樱花动画和对话排版的开发速度明显快了一截，同时完整保留了原先的模块边界。

Prompt 长度与表达自然度的取舍

为了防角色跑偏加了很多约束条款，但规则写太满后，角色在日常闲聊里容易显得生硬；另外对话历史目前只在内存保存，后续需要补数据库持久化。

市场数据与品类背景

5000万 DAU 峰值
5亿$+ 累计收入
29倍 同比增长
1000h 个人游戏时长

2025 年射击市场里纯单模式已经很难拉开差距，腾讯射击品类只占约 7% 的产品数量，却拿走了前 100 移动游戏 18.29% 的收入。《三角洲行动》靠搜打撤模式把 DAU 拉到 3000 万级别，站稳了长线运营位置。

实战体验：信息差与伏击博弈

我自己的打法：前期避开正面拼枪，先摸干净外围资源，听枪声和看剩余人数推算敌队动线，卡在撤离必经点打刚交完火、状态不满的队伍（俗称“老鼠打法”）。
01

预判动线比纯拼枪更上头

1000 小时下来枪法不差，但真正留住我的时刻，往往是算准对方撤离路线、提前架好点位打完一套收割，比硬刚正面有成就感。

02

信息不对等撑起紧张感

侦察技能、脚步声和枪声方位构成了另一套战力。我知道你在哪、你不知道我在哪，搜打撤大部分心理压力都来自这层信息差。

03

低成本撬动高装备收益

低配进图也有机会靠卡位把满编高装队放倒，这种以小博大的可能性让每一局都有翻盘悬念。

经济系统：哈夫币与梯度地图

收益与风险的平衡点

物资给太松容易很快毕业，给太紧又会让普通玩家反复破产弃坑。三角洲的做法是靠三档地图拉开梯度：普通图保底，机密和绝密图抬高准入门槛和期望回报，再用安全箱保住最值钱的一两件物品，帮新手扛住阵亡挫败。

通胀痛点与替代思路

开服承诺过「仓库永久不清空」，后期通胀压不住时只能暗砍爆率或限制撤离，每次改动都很容易惹怒玩家。参考 ARC Raiders 的思路，可以做可选的「赛季远征」：达到门槛后允许硬核玩家自愿重置进度换限定外观与下赛季加成，休闲玩家不受影响，经济也能自然回笼。

版本事故与反思

2025.10「共享监狱」风波

玩家在最高难度图「潮汐监狱」用防御干员深蓝通过暗号自发结盟搜图撤离。官方为控通胀紧急限制撤离人数并削弱干员，结果触发大规模差评。这背后是玩家自发玩法和官方经济指标之间的直接冲突，比起一刀切封堵，在地图机制上区分合作撤离与竞争撤离会更稳妥。

最想问项目组的问题

如果有机会和主策聊，我最想问匹配算法怎么分池。地图动线、干员技能和经济梯度做得再细，一旦把实力和装备差距太大的队伍排进同一局，普通玩家记住的就只有被单方面碾压。

强玩法模拟经营手游市场观察

市场笔记

整理《无尽冬日》《三国：谋定天下》《Top Heroes》《Kingshot》等案例，看轻量入口如何承接重度策略留存。

为什么「轻量入口 + 重度内核」跑得通

存量市场买量越来越贵，直接把传统 SLG 甩给新用户，前期流失太高。《无尽冬日》和《Top Heroes》都用了同一个办法：开头用模拟经营或自动探索接住碎片时间，前 7—10 天靠建造和收集稳住次留、七留，再逐步放开联盟对抗和重度数值。

几款常玩游戏给我的启发

《泰拉瑞亚》2000h：用奖励条件改变打法

很多套装效果给的数值并不夸张，但触发条件会推着玩家换一套打法。我做《超时空激战》的「隐身镀层」就是照这个思路：长时间不受伤抵一次伤害，拿了它就会下意识把走位抠细。

《杀戮尖塔》：限制选项数量才有取舍感

一次摊十张牌出来反而让人懒得细看，三选一才逼着人去算眼下缺什么、后面想凑什么套路。这套权重池加三选一的结构，我直接用在了《超时空激战》的词条升级里。

《俄罗斯钓鱼 4》& 搜打撤：把重复痛点做成系统

玩《逃离塔科夫》和《三角洲》时，满包跑撤离点的紧张感最难忘，后来写成了《猎魂传奇》的节点循环；玩《俄罗斯钓鱼 4》时被重复收线和盯三竿折腾久了，干脆用 OpenCV 和音频频谱做了套自动化助手。
